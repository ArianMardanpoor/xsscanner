🖥️ Serving on a server and opening it in the browser

      
Three ways; the first one is the simplest

      
    
        
  1. Serve the results folder — on the server:
    cd ~/tools/xsscanner/results
python3 -m http.server 8877 --bind 127.0.0.1
    2. 
        
  2. Copy the viewer into results — put xsscanner-viewer.html in that folder:
    cp xsscanner-viewer.html ~/tools/xsscanner/results/
# then open in your browser:  http://SERVER_IP:8877/xsscanner-viewer.html
    3. 
        
  3. SSH tunnel (if the port is not reachable):
    ssh -L 8877:127.0.0.1:8877 root@hunt-server
# then open in your local browser:  http://localhost:8877/xsscanner-viewer.html
    4. 
      

      
⚠️ Scan results contain sensitive URLs; bind the server to 127.0.0.1 only and do not expose it to the outside, or use an SSH tunnel.

    

    

      
📂 Files the viewer reads

      

        
FileDescription

        
          
results/raw_findings.jsonlThe tool's raw findings — one JSON per line. The main source for the Findings tab

          
results/cleanup_audit.jsonlAudit events (parameter caps, dedup, …) — Cleanup Audit tab

          
results/TARGET_REPORT.mdThe final text report — MD Report tab

          
Terminal output (log)Run log text — Run Log tab; VULN FOUND blocks are extracted and can be added as findings

        
      

      
You can also load all of these by dragging & dropping them onto the page; the viewer uses the file name to decide where each file goes. No data ever leaves your browser — everything is processed offline inside the page.

    

  

  

    
🧭 How do I spot false positives?

    
A suggested triage framework for sorting 250 raw findings

    

      
SignMeaningAction

      
        
Real payload + snippet/executionA genuinely malicious payload (not just a canary) is reflected, ideally with DOM/execution evidenceConfirm → report

        
Canary only (x9canary)The parameter is reflected, but the payload was only a discovery marker; not proof of executionTest manually: send a real payload

        
CSP in the tool's noteReflection exists, but a strict CSP probably blocks executionCheck the reflection context; XSS is only valid in the right context

        
Noisy parameters (_, callback, utm_*, token…)Standard app behavior (JSONP, analytics, anti-CSRF) — not a vulnerabilityFalse positive → drop from the report

        
Chunk repetition (chunk 3/3)The same earlier finding re-confirmed in a later chunk — the viewer dedupes it automaticallyNo action needed
